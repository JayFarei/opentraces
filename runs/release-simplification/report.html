01 The workflow

A contract-driven pipeline, defended against three failure modes

The documented feature set was captured once as a non-regression contract and passed verbatim into every agent. No implementer ever judged its own output.

[01] Agentic laziness

Every theme reaches a terminal state. A theme only "passes" with status=pass and zero blocker/major findings.

Result: 4 verified, 0 declared-done-early.

[02] Self-preferential bias

Each worktree got a separate Opus verifier in a clean context that re-read the diff and re-ran the tests itself.

Result: t4 caught + corrected during re-verification.

[03] Goal drift

The feature map (FEATURE-MAP.json) was the contract, threaded verbatim into discovery, implementation and verification.

Result: full CLI surface + 3 version numbers intact.
