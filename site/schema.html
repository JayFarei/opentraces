Schema Reference

Complete JSONL schema for opentraces trace records. Each line in the dataset is a single TraceRecord. Version 0.1.0.

Traces are stored as JSONL (one JSON object per line). Each object is a self-contained TraceRecord that can be processed independently.

TraceRecord object

Top-level record representing a single agent session or conversation. This is the root object in each line of the JSONL file.

Field Type Description
trace_id required string
Unique identifier for this trace record. Used for deduplication across datasets.
"tr_a8f3c1b7e9d2"
session_id required string
Links multiple traces from the same conversation session. Multi-turn interactions share this ID.
"sess_7b2e4f91"
Enables multi-turn trajectory analysis for RL training
agent required string
Identifier for the coding agent that generated this trace.
"claude-code" | "cursor" | "copilot" | "aider"
model required string
The LLM model ID used for this session. Follows provider naming conventions.
"claude-sonnet-4-20250514"
Enables cross-model comparison and model-specific fine-tuning
timestamp required string (ISO 8601)
When this trace was recorded. UTC timezone.
"2026-03-27T14:32:00Z"
steps required Step[]
Ordered sequence of agent actions and observations. Each step is one turn in the conversation.
Core training data: the action sequence that models learn from
outcome required Outcome
Success/failure signal for the overall session, with task type and confidence.
The reward signal that makes this data useful for RL
attribution optional Attribution
Links code output to the conversation turns that produced it. Compatible with the Agent Trace attribution spec.
sub_agents optional SubAgent[]
Child agent invocations within this session. Captures delegation hierarchy.
Enables orchestration research and multi-agent analysis
security_tier required integer (1-3)
Which security processing tier was applied before upload.
2
redacted_fields optional string[]
JSON paths of fields that were redacted during security processing. Allows consumers to know what data was removed.
["steps.0.tool_calls.0.input.content"]
contributor_id optional string
Pseudonymous contributor identifier. Not linked to real identity unless the contributor opts in.
schema_version required string (semver)
Schema version for forward/backward compatibility.
"0.1.0"

Step object

A single turn in the agent conversation. Can be an assistant action (with tool calls) or a user/system message.

FieldTypeDescription
role required string
The role of this conversation turn.
"user" | "assistant" | "system" | "tool"
content optional string
Text content of this turn. May be redacted based on security tier.
tool_calls optional ToolCall[]
Tool invocations made during this step. Only present for assistant turns that use tools.
token_usage optional TokenUsage
Token consumption for this step, including cache metrics.
timestamp optional string (ISO 8601)
When this step occurred. Enables latency analysis between steps.
duration_ms optional integer
Wall-clock time for this step in milliseconds.
2340

ToolCall object

A single tool invocation within a step. Captures what the agent did and what happened.

FieldTypeDescription
tool required string
Name of the tool that was invoked.
"edit_file" | "run_command" | "search" | "read_file"
Key feature for tool usage pattern analysis
input required object
Arguments passed to the tool. Structure varies by tool type. May be partially redacted.
output optional object
Result returned by the tool. Includes success/failure status and any returned data.
error optional string
Error message if the tool call failed. Null or absent for successful calls.
Error recovery is a high-value training signal
duration_ms optional integer
How long the tool call took in milliseconds.
450

TokenUsage object

Token consumption metrics for a single step. Essential for cost analysis and efficiency research.

FieldTypeDescription
input required integer
Number of input tokens (prompt) for this step.
1847
output required integer
Number of output tokens (completion) for this step.
342
cache_read optional integer
Tokens served from cache rather than recomputed. Critical for understanding cache efficiency.
12840
Cache hit rates are a key efficiency metric for agent optimization
cache_write optional integer
Tokens written to cache during this step.
2048

Outcome object

The result signal for the entire trace. This is what makes the data useful for reward modeling and RL.

Outcome is the most valuable field in the schema. It provides the reward signal that synthetic benchmarks cannot. Real developer judgments about whether the agent actually helped.
FieldTypeDescription
success required boolean
Whether the session achieved its intended goal. Binary signal derived from explicit user feedback or heuristic detection.
task_type optional string
Classification of what the agent was trying to do.
"bug_fix" | "feature" | "refactor" | "test" | "docs" | "debug" | "explore"
Enables task-specific training and performance analysis
confidence optional float (0-1)
How confident the outcome assessment is. 1.0 = explicit user signal, lower values = heuristic inference.
0.92
signal_source optional string
How the outcome was determined.
"user_explicit" | "test_pass" | "commit" | "heuristic"

Attribution object

Links code output back to the conversation turns that produced it. Compatible with the Agent Trace attribution specification.

FieldTypeDescription
snippets required Snippet[]
Code snippets produced during this session, each linked to the step that created them.
commit_sha optional string
Git commit SHA if the changes were committed.
"a1b2c3d4e5f6"
repo optional string
Repository identifier. Only included for public repositories.
"github.com/user/repo"

Snippet object

A piece of code produced or modified during the session, with full lineage to the conversation.

FieldTypeDescription
file required string
Relative file path within the repository.
"src/auth.ts"
lines required [int, int]
Start and end line numbers (inclusive) of the modified region.
[42, 67]
step_ref required integer
Index into the steps array indicating which conversation turn produced this snippet.
0
Links code to conversation context for training on code generation
language optional string
Programming language of the snippet.
"typescript" | "python" | "rust"
action optional string
What happened to this code.
"created" | "modified" | "deleted"

SubAgent object

Represents a child agent invoked by the parent during this session. Captures the delegation hierarchy for orchestration research.

FieldTypeDescription
agent required string
Identifier for the sub-agent.
"code-reviewer" | "test-runner"
model optional string
Model used by the sub-agent, if different from the parent.
step_ref required integer
Index into the parent steps array where this sub-agent was invoked.
trace_id optional string
If the sub-agent's trace is also in the dataset, this links to it. Enables hierarchical trace reconstruction.
outcome optional Outcome
Success/failure signal for the sub-agent's task specifically.

Training Use Cases

How each field maps to ML training objectives. This is why the schema looks the way it does.

Use Case Key Fields Description
Reward Modeling outcome, steps
Train reward models on real developer outcomes. Use outcome.success as the reward signal, steps as the trajectory.
Tool Use SFT steps.tool_calls
Supervised fine-tuning on tool selection and argument construction. Filter for successful outcomes to get high-quality demonstrations.
Efficiency Research token_usage, duration_ms
Study cache utilization patterns, identify expensive strategies, optimize token budgets.
Orchestration sub_agents, steps
Analyze multi-agent delegation patterns. Which sub-agent strategies lead to better outcomes?
Code Generation attribution.snippets
Link conversation context to code output for training code generation models with rich context windows.
Error Recovery tool_calls.error, steps
Train models to recover from tool failures. Sequences where errors occur followed by successful corrections are high-value training data.
