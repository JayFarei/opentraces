# Mining Claude Reasoning Tokens: Accessibility, Extraction, and Upstream Utility

## Executive Summary

The short answer is: **no one has found a way to decrypt or reverse-engineer Claude's thinking block signatures**, and there is no viable path to doing so. The signature field is a one-way cryptographic integrity proof, not an encryption envelope, and Anthropic has deliberately designed the system to prevent extraction of raw reasoning tokens [1][2]. For Claude 4 models, the API returns only a *summary* of the thinking process (generated by a separate, smaller model), while the full chain-of-thought is encrypted into the signature and never exposed to developers by default [3][4]. The only official path to full thinking output on Claude 4 is Anthropic's "Developer Mode," available by contacting their sales team [3]. Meanwhile, the community has taken several alternative approaches to extract value from Claude traces: (a) behavior cloning via synthetic data generation, where groups like TeichAI distilled Claude Opus 4.5's reasoning patterns into open-weight models for $52 using just 250 samples [5]; (b) session JSONL parsing tools that extract everything except thinking content from Claude Code logs [6][7]; (c) Anthropic's own open-source circuit tracing library for mechanistic interpretability of open-weight models [8]; and (d) the open-r1 ecosystem on HuggingFace, which collects reasoning traces from models that do expose them (DeepSeek R1, QwQ-32B) for downstream training [9]. The fundamental asymmetry is clear: closed models (Claude, OpenAI o1/o3) hide reasoning tokens behind cryptographic barriers while billing for them, while open models (DeepSeek R1, Qwen3) expose full `<think>` traces that anyone can collect, distill, and train on [10][11]. For a community trace dataset like opentraces, this means Claude traces will contain rich tool-use, code attribution, and response data, but reasoning chains will remain a black box unless Anthropic changes its policy or the user has Developer Mode access.

---

## 1. Introduction

The investigation that prompted this research identified two distinct variants of Claude thinking blocks in session JSONL files. Variant A (dominant on Sonnet, present on ~54% of Opus responses) contains plaintext thinking text with a cryptographic signature. Variant B (present on ~46% of Opus responses) contains an empty string in the thinking field with a signature that is sometimes very large (up to 66K characters) and contains protobuf-encoded metadata including the model name [12][13]. The central question is whether anyone in the community has found a way to extract, decode, or otherwise make use of Claude's reasoning tokens for upstream purposes, including training, evaluation, or dataset construction.

This report surveys the technical architecture of Claude's thinking system, the cryptographic properties of the signature field, community attempts at extraction and reverse engineering, the policy landscape around reasoning token accessibility, alternative approaches to capturing reasoning value from closed models, and the open-model ecosystem that provides reasoning traces by design.

## 2. Architecture of Claude's Thinking System

### 2.1 How Extended Thinking Works

Extended thinking gives Claude enhanced reasoning capabilities by allowing it to generate internal "thinking" content blocks before producing a final response [1]. When enabled via the API, the model allocates a configurable token budget (minimum 1,024 tokens) for internal reasoning. The thinking appears in the response as structured content blocks of type `"thinking"`, alongside the final `"text"` blocks and any `"tool_use"` blocks [1][3].

Claude 4 models (Opus 4, Sonnet 4, and their 4.5/4.6 variants) introduced a fundamental change: the API returns a *summary* of Claude's thinking rather than the raw output [3]. This summarization is performed by a separate, smaller model that the primary thinking model never sees [3]. The full thinking process is encrypted and folded into the `signature` field. Anthropic states that summarization preserves the "key ideas" with minimal added latency, and is only required approximately 5% of the time, as most thinking processes are short enough to display in full [3].

Claude Sonnet 3.7 remains the only model that returns full, unsummarized thinking output by default [3].

### 2.2 The Signature Field

Every thinking block includes a `signature` field, which Anthropic describes as "opaque" and states should not be interpreted or parsed [1][2]. The signature serves two purposes: (a) cryptographic verification that the thinking block was generated by Claude (preventing forgery when blocks are passed back to the API), and (b) carrying the encrypted full thinking content for server-side reconstruction during multi-turn conversations [2][14].

When streaming, the signature arrives as a `signature_delta` event just before `content_block_stop` [1]. Signature values are significantly longer in Claude 4 models than in Claude 3.7, consistent with the full thinking content being folded into the signature rather than returned in plaintext [13][15]. Signatures are cross-platform compatible across Claude API, Amazon Bedrock, and Vertex AI [2].

### 2.3 The `display` Parameter

The `display` field on the thinking configuration accepts two values [16]:

- `"summarized"` (default): Thinking blocks contain summarized text, signature carries encrypted full thinking.
- `"omitted"`: Thinking blocks return with an empty thinking field. The signature still carries the encrypted full thinking. The benefit is faster time-to-first-text-token since the server skips streaming thinking tokens entirely [16].

Critically, you are still billed for full thinking tokens regardless of display mode [16]. The `"omitted"` setting explains Variant B from the original investigation: Claude Code may be using `display: "omitted"` for certain requests, or the Claude 4 model is defaulting to this behavior for Opus in certain configurations.

### 2.4 Redacted Thinking (Claude 3.7 Only)

When Claude 3.7 Sonnet's internal reasoning triggers safety systems, Anthropic encrypts some or all of the thinking block and returns it as a `redacted_thinking` block with opaque `data` [2][17]. These blocks are automatically decrypted server-side when passed back to the API. Claude 4 models handle thinking differently and do not produce redacted thinking blocks [17].

### 2.5 Billing Implications

Thinking tokens are billed as output tokens at the model's standard rate: $25/M output tokens for Opus 4.6 [18][19]. You are charged for the full thinking process, not the summary you see [3]. A single complex query might generate 200 visible tokens and 2,000+ hidden reasoning tokens, all billed at the output rate [10]. This creates a trust deficit among developers who cannot see what they are paying for [19][20].

## 3. Can the Signature Be Decoded?

### 3.1 Cryptographic Properties

The signature field is a base64-encoded binary blob that exhibits patterns consistent with Protocol Buffers (protobuf) encoding [13][15]. Community analysis has confirmed that protobuf is a dependency within Claude Code's bundled source [21]. The base64 strings (e.g., `EqQBCgIYAhIM...`, `EoAC...`) contain structured binary data including metadata such as model name and version [13].

However, the reasoning content within the signature is encrypted, not merely encoded. Anthropic's documentation explicitly states that the server "decrypts the signature to reconstruct the original thinking for prompt construction" [2][14]. The encryption uses Anthropic's server-side keys, meaning:

1. The signature is not a simple hash or HMAC that could be reversed.
2. The encryption keys are held server-side and never exposed to clients.
3. There is no client-side decryption API or endpoint.
4. Anthropic's "Confidential Inference" infrastructure uses trusted VMs specifically to protect this kind of data [22].

### 3.2 Community Attempts at Reverse Engineering

No public report has successfully decoded thinking content from the signature field. The closest investigation is the LessWrong post "Did I Catch Claude Cheating?" [23], which found that:

- Some thinking content appears in `"text"` or code comment blocks *without* a signature, suggesting that unsigned reasoning fragments can occasionally leak into non-thinking blocks.
- The signature in `"thinking"` blocks is present but opaque; the author could not extract reasoning content from it.
- The author proposed that Anthropic's API layer only expects signature values in `thinking` types when post-processing, and unsigned thinking may exist in other block types.

The GitHub project `claude-code-reverse` [21] visualized Claude Code's LLM interactions by intercepting API requests and responses, but this only captures what the API returns (summarized or omitted thinking), not the encrypted full thinking.

### 3.3 The Definitive Answer

**There is no way to decrypt Variant B signatures.** The signature is a server-side encrypted blob using keys that only Anthropic holds. It is not an encryption envelope designed for client-side decryption. The protobuf metadata (model name, version) is structural overhead, not the reasoning content itself. No public tool, hack, or technique can recover the full thinking from the signature field.

## 4. Official Paths to Full Thinking Access

### 4.1 Claude Sonnet 3.7

The only Claude model that returns full, unsummarized thinking output by default. If your use case requires visible reasoning traces, Sonnet 3.7 is the path of least resistance [3].

### 4.2 Developer Mode (Claude 4+)

Anthropic has announced a "Developer Mode" for users requiring raw chain-of-thought access on Claude 4 models [3]. This is only available by contacting Anthropic's sales team. No public documentation exists on what Developer Mode entails in terms of pricing, rate limits, or terms of use. It is likely gated behind enterprise agreements that include restrictions on using the reasoning output for training competing models.

### 4.3 The Think Tool (Separate Mechanism)

Anthropic also offers a "think tool," which is a different mechanism entirely [24]. This is a tool-use pattern where Claude is prompted to write its reasoning into a designated tool call, making it visible in the response. However, this is not the same as extended thinking: it produces structured reasoning text that the model generates explicitly, not the internal chain-of-thought that extended thinking captures. The think tool output is fully visible and unencrypted, but it lacks the depth and spontaneity of native extended thinking.

## 5. Community Approaches to Mining Claude Traces

### 5.1 Session JSONL Parsing

The community has built a rich ecosystem of tools for parsing Claude Code's local JSONL session files (`~/.claude/projects/{project}/{session-id}.jsonl`) [6][7][25][26]:

- **claude-code-transcripts** (Simon Willison): Converts sessions to clean HTML with pagination [6].
- **claude-code-log**: Python CLI producing HTML/Markdown with TUI browsing, token usage tracking, and thinking content rendering [25].
- **claude-JSONL-browser**: Web-based tool with search across conversations and export options [26].
- **ccusage**: CLI for usage analytics by date, session, or project [27].
- **claude-devtools**: Local app that reconstructs file reads, writes, searches, and tool calls into a structured interface [28].

These tools extract everything the session contains: user prompts, assistant responses, tool calls and results, timestamps, and token counts. However, for Claude 4 models, the thinking field is empty in the JSONL, rendering thinking extraction impossible from local files [13][15].

A feature request (Issue #31143) asks Anthropic to persist the summarized thinking text to the JSONL, since even the summary is currently not written to disk [15]. As of March 2026, this has not been implemented.

### 5.2 Behavior Cloning via Synthetic Data

The most successful approach to extracting reasoning value from Claude does not involve decoding signatures at all. Instead, it treats the model as a black box and captures its *behavior* rather than its *internals*.

**TeichAI** is the most striking example: a non-profit group of college students that distilled Claude Opus 4.5's reasoning patterns into open-weight models [5][29]. Their pipeline:

1. Use PromptGen (an open-source tool) to generate hundreds of complex reasoning problems.
2. Send prompts to Claude's API with reasoning effort set to high, capturing the full response including whatever thinking summary is returned.
3. Fine-tune open-weight models (Qwen3, GLM-4.7, Nemotron) using Unsloth for supervised fine-tuning.

With just 250 training samples and $52.30 in API costs, they produced models downloaded over 67,000 times on HuggingFace [5]. Their Claude 4.5 Opus collection spans 15 releases across multiple architectures [29]. Every model ships in GGUF format with quantizations from 2-bit to 16-bit, designed for local deployment [29].

The uncomfortable implication: reasoning patterns, the structured thinking, self-correction, and problem decomposition that make frontier models valuable, can be partially transferred with remarkably little data [5].

### 5.3 Industrial-Scale Distillation (The Adversarial Case)

Anthropic identified industrial-scale distillation campaigns by DeepSeek, Moonshot, and MiniMax, which generated over 16 million exchanges with Claude through approximately 24,000 fraudulent accounts [30][31]. Key techniques included:

- Prompting Claude to "imagine and articulate the internal reasoning behind a completed response and write it out step by step," effectively generating chain-of-thought training data at scale [30].
- Moonshot specifically attempted to extract and reconstruct Claude's reasoning traces in a targeted later phase [30].
- MiniMax's 13 million exchanges targeted agentic coding, tool use, and orchestration [30].

The scale: DeepSeek (150K+ exchanges), Moonshot (3.4M+ exchanges), MiniMax (13M exchanges) [30]. This demonstrates that even without decrypting signatures, the *behavioral output* of reasoning models contains enough signal for capability transfer.

### 5.4 Anthropic's Circuit Tracing (Mechanistic Interpretability)

Anthropic open-sourced a circuit tracing library in May 2025 that generates "attribution graphs" revealing internal reasoning steps in LLMs [8][32]. The library uses cross-layer MLP transcoders to replace raw neurons with interpretable features, then builds sparse graphs of how information flows from input to output [8].

This is powerful for understanding *how* models reason, but it only works on open-weight models (Gemma-2-2B, Llama-3.2-1B, Qwen3-4B) [8][32]. It cannot be applied to Claude itself because the weights are not publicly available. The tool is relevant for researchers building their own reasoning models, not for extracting Claude's reasoning traces.

## 6. The Open-Model Alternative

### 6.1 DeepSeek R1: Full Reasoning Transparency

DeepSeek R1 represents the polar opposite of Claude's approach. Its reasoning traces are fully visible via `<think>...</think>` tags, the weights are MIT-licensed, and anyone can collect, distill, and train on its chain-of-thought output [10][11][33].

R1's reasoning was trained purely through reinforcement learning without supervised fine-tuning, demonstrating that reasoning capabilities can be incentivized through RL alone [33]. The distilled variants (R1-Distill-Qwen-7B, etc.) use supervised fine-tuning from teacher-generated reasoning traces to transfer multi-step chain-of-thought capabilities [34].

Known quirks include occasional Chinese characters in English reasoning traces (a bilingual training artifact) and significantly longer response times due to verbose thinking [10][11].

### 6.2 HuggingFace Reasoning Trace Datasets

The open-r1 collection on HuggingFace hosts community reasoning trace datasets [9]:

- 17K reasoning traces for coding and math distilled from DeepSeek-R1.
- 114K reasoning traces covering math, science, code, and puzzles.
- CHIMERA (2026): Synthetic reasoning dataset with long-horizon traces and domain diversity [35].
- SmolLM3 training mixture with and without reasoning traces [36].

These datasets are exclusively from open models (DeepSeek R1, QwQ-32B, Qwen3, AM-Thinking-v1). No dataset on HuggingFace contains Claude's internal reasoning traces, because they are not accessible.

### 6.3 Agent Trace Datasets

For agent-level traces (tool use, multi-step execution), several relevant datasets exist:

- **neulab/agent-data-collection**: Comprehensive agent interaction trajectories following the Agent Data Protocol schema [37].
- **PatronusAI/TRAIL**: 148 annotated agent execution traces with 841 errors, collected via OpenTelemetry [38].
- **OpenCUA/AgentNet**: 22.6K human-annotated computer-use tasks across desktop OSes [39].
- **DeepNLP/Agent-RL-Open-Dataset**: Real-world RL agent data with user feedback rewards [40].

These datasets capture behavioral traces (actions, tool calls, observations) rather than internal reasoning, making them compatible with what can be extracted from Claude sessions even without thinking content.

## 7. The Accessibility Spectrum

### 7.1 Comparison Matrix

| Model | Reasoning Visible | Weights Available | Reasoning Billable | Distillation Policy |
|-------|------------------|-------------------|-------------------|-------------------|
| Claude 3.7 Sonnet | Full plaintext | No | Yes (output rate) | Prohibited by ToS |
| Claude 4+ (default) | Summary only | No | Yes (full, not summary) | Prohibited by ToS |
| Claude 4+ (Developer Mode) | Full (enterprise) | No | Yes | Restricted by agreement |
| OpenAI o1/o3 | Hidden entirely | No | Yes (output rate) | Prohibited by ToS |
| DeepSeek R1 | Full `<think>` tags | Yes (MIT) | Varies by provider | Explicitly permitted |
| Qwen3/QwQ-32B | Full `<think>` tags | Yes | Varies by provider | Permitted |

### 7.2 Policy Tensions

The debate around reasoning token accessibility sits at the intersection of safety, competition, and governance [41][42]:

- **Safety argument**: Hiding reasoning prevents misuse of internal deliberation that may contain unaligned content (e.g., reasoning about bypassing safety filters) [10].
- **Competition argument**: Reasoning patterns are the primary moat for frontier labs; exposing them enables cheap distillation [30][41].
- **Governance argument**: Capability is more portable than control. When useful behavior can be transferred more cheaply than the governance structure that accompanied it, the safety benefits of closed reasoning are undermined [42].
- **Transparency argument**: Developers paying for reasoning tokens they cannot see face a trust deficit, and cannot debug, audit, or improve their systems effectively [19][20].

A 2026 paper proposes "distillation resistance" at the architectural level, where high-level capability is coupled to internal stability constraints that make it less compressible, reducing the value of distillation as a shortcut [42]. This represents a potential future direction where models could be more transparent about reasoning without enabling easy capability transfer.

## 8. Implications for opentraces

### 8.1 What Can Be Captured from Claude Traces

Given the current architecture, a community trace dataset collecting Claude Code sessions can capture:

1. **Full conversation structure**: User prompts, assistant text responses, timestamps.
2. **Tool use chains**: Every Bash command, file read, file edit, web search, and their results.
3. **Code attribution**: Which files were created/modified, the exact changes, and the context that prompted them.
4. **Token metrics**: Input/output token counts, cache hit rates.
5. **Thinking metadata**: The fact that thinking occurred (type, signature presence), but not the content.
6. **Thinking summaries** (if captured during streaming): The summarized thinking text that appears in the TUI, but only if the collection pipeline intercepts the streaming response before it reaches the JSONL persistence layer (which currently discards it) [15].

### 8.2 What Cannot Be Captured

1. **Full reasoning chains**: The raw chain-of-thought is encrypted and inaccessible.
2. **Thinking summaries from JSONL**: Currently not persisted to disk [15].
3. **Reasoning effort/quality metrics**: No signal on how much thinking was "useful" vs. exploratory.

### 8.3 Recommended Approaches

For a trace dataset aiming for upstream training utility:

1. **Maximize behavioral signal**: Focus on tool-use chains, code diffs, and the relationship between prompts and outcomes. These are highly informative for training agent policies even without reasoning traces.
2. **Intercept streaming summaries**: If technically feasible, capture thinking summaries from the streaming API before they are discarded. This provides partial reasoning visibility.
3. **Complement with open-model traces**: Pair Claude behavioral traces with DeepSeek R1 or Qwen3 reasoning traces on equivalent tasks to create a dataset with both high-quality actions and visible reasoning.
4. **Watch for Developer Mode changes**: If Anthropic broadens Developer Mode access or changes the summarization policy, the dataset schema should be ready to accommodate full thinking content.
5. **Use the think tool pattern**: For sessions where reasoning visibility is critical, the think tool (a tool-use prompt pattern, not extended thinking) produces visible, unencrypted reasoning that can be captured [24].

## 9. Synthesis and Novel Insights

### 9.1 The Summarization Bottleneck

The most underappreciated aspect of Claude's thinking architecture is that the summarization model creates an information bottleneck that even Anthropic may not fully control. The summary model is separate from the thinking model and operates independently [3]. This means the summary is a lossy compression of the full reasoning, and the fidelity of that compression is opaque to everyone, including Anthropic's customers with Developer Mode access (who see the full thinking but not how it differs from the summary that other users see).

### 9.2 The $52 Lesson

TeichAI's success with 250 samples suggests that the reasoning *patterns* are far more compressible than the reasoning *content*. You do not need to see Claude's internal chain-of-thought to capture its reasoning style. The behavioral output, the way it structures problems, sequences tool calls, and builds up solutions, contains enough signal for meaningful capability transfer [5]. This has profound implications for trace dataset design: even without thinking content, Claude Code session traces may contain enough behavioral signal to be valuable for training.

### 9.3 The Convergence Toward Hybrid Datasets

The most useful training datasets in 2026-2027 will likely be hybrid: behavioral traces from closed models (rich in real-world tool use and code generation quality) combined with reasoning traces from open models (providing the chain-of-thought supervision). This is already happening informally through projects like open-r1 [9] and the Agent Data Protocol [37], and represents the most practical path forward for community trace projects.

## 10. Limitations and Caveats

1. **Anthropic's architecture evolves rapidly.** The thinking system has changed significantly across Claude 3.7, 4.0, 4.5, and 4.6. Future versions may change the summarization policy or signature format.
2. **Developer Mode details are unverified.** No public documentation exists on Developer Mode's terms, pricing, or restrictions. The information comes from Anthropic's marketing materials [3].
3. **The distillation accusations are Anthropic's claims.** The 16M exchange figure comes from Anthropic's own investigation; independent verification is limited [30][31].
4. **Legal landscape is unsettled.** Whether capturing and sharing model outputs (even behavioral, non-reasoning traces) for training constitutes fair use or ToS violation varies by jurisdiction and is actively litigated.
5. **No sources were found addressing whether Anthropic plans to change reasoning token accessibility in response to community demand.** The feature request to persist thinking summaries to JSONL (Issue #31143) has no official response as of March 2026 [15].

---

## 11. Recommendations

### Immediate Actions

1. **Schema readiness**: Ensure the opentraces schema has optional fields for thinking summaries, thinking metadata (budget, effort level), and full thinking content, even if most traces will have these empty. This future-proofs the format.
2. **Streaming interception**: Investigate whether Claude Code hooks or MCP middleware can capture thinking summaries from the streaming API before they are discarded by the JSONL persistence layer.
3. **Open-model companion dataset**: Consider a parallel collection effort using DeepSeek R1 or Qwen3 on equivalent coding tasks, producing traces with full reasoning visibility that complement the Claude behavioral traces.

### Further Research

1. Track Anthropic's Developer Mode expansion and any API changes to thinking block accessibility.
2. Monitor the feature request for persisting thinking summaries to session JSONL (anthropics/claude-code#31143).
3. Evaluate whether the think tool pattern produces reasoning traces of comparable quality to native extended thinking for specific task types.
4. Research the legal boundaries of collecting and sharing model behavioral outputs (non-reasoning traces) under current ToS and fair use doctrine.

## Methodology

This report was produced using ultradeep research methodology with 18 parallel web searches across 10 distinct research angles: Claude thinking block architecture, signature cryptography, community reverse-engineering attempts, JSONL session parsing tools, reasoning token accessibility across model families, open-model reasoning trace datasets, distillation policy and practice, mechanistic interpretability tools, agent trace collection protocols, and billing/cost transparency. Sources were triangulated across official documentation (Anthropic, AWS, OpenAI), community projects (GitHub), academic papers (arXiv), news reporting (CNBC, TechCrunch, InfoQ), and developer blogs (Simon Willison, LessWrong, DEV Community). The report prioritizes primary sources (official docs, direct GitHub issues) over secondary reporting, and distinguishes between verified technical facts and claims made by interested parties (e.g., Anthropic's distillation accusations).
